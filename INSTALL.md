# Установка AMG

AMG ставится двумя способами: **вручную** (вы выполняете шаги) или **силами модели** — достаточно сказать ей «установи AMG по INSTALL.md», и она задаст вопросы и всё настроит (раздел 2). В обоих случаях **граф всегда локальный** — он лежит в `<проект>/.claude/amg/` даже при глобальной установке движка, потому что память относится к конкретному проекту; общего графа между проектами нет. Требуется Python 3; опциональные зависимости — ниже.

Что куда ставится: **управляющая плоскость** (движок) — это каталоги `agents/` и `skills/`, сниппет активации в `CLAUDE.md` и файл `config.yml`. **Контентная плоскость** (сам граф) создаётся при первом запуске в `<проект>/.claude/amg/`.

## Раздел 1. Ручная установка

### Локально (в один проект)

1. **Разместить движок.** Скопировать `agents/` и `skills/` в `<проект>/.claude/` (то есть `<проект>/.claude/agents/` и `<проект>/.claude/skills/`).
2. **Создать конфиг** `<проект>/.claude/amg/config.yml` — минимально нужны активация, рабочий язык и источники:

```yaml
active: true
working_language: ru
mirror_path:           # что редактируется — граф держится равным (список или строка)
  - src
absorb_path:           # разовое сырьё — впитывается один раз
  - docs/legacy
```

3. **Дописать блок AMG в `CLAUDE.md`** проекта (`<проект>/CLAUDE.md`; если файла нет — создать). Блок добавляется в **конец**, между маркерами, чтобы ваши инструкции оставались первыми, а переустановка заменяла только его:

```markdown
<!-- AMG:BEGIN -->
## Ассоциативная память (AMG)
Если в `.claude/amg/config.yml` есть `active: true`, веди память по петле:
1. В начале сессии: проиграть незавершённые записи и свести граф с диском
   (`graph_store.py recover`, `verify --repair`, затем `reconcile.py bootstrap .`,
   если источники могли измениться).
2. Перед каждой задачей и при смене фокуса: собрать пакет контекста
   (скилл `amg-retrieve`) и работать по нему.
3. По ходу: фиксировать решения и выводы узлами `notes`.
4. В конце сессии (перед `/clear`): консолидация (скилл `amg-consolidate`)
   и выгрузка диалога в `.claude/amg/sessions/`.
Не редактировать сами скиллы, агенты и скрипты AMG в рамках задачи — это
инфраструктура; о багах сообщать пользователю. При несогласованности —
`recover` + `verify --repair` + `reconcile.py bootstrap .`.
<!-- AMG:END -->
```

4. **(Опционально) поставить зависимости** — `pip install -r requirements.txt` или нужное подмножество (см. «Опциональные зависимости» ниже).
5. **Проверить установку:**

```
python .claude/skills/amg-bootstrap/scripts/graph_store.py verify --repair
python .claude/skills/amg-bootstrap/scripts/reconcile.py bootstrap .
python .claude/skills/amg-bootstrap/scripts/extract_structure.py . --stats
```

`verify` должен сообщить, что всё чисто; `bootstrap` построит граф; `--stats` покажет, какие файлы попали и каких опциональных извлекателей не хватает.

### Глобально (движок на все проекты)

1. **Разместить движок один раз** — скопировать `agents/` и `skills/` в `~/.claude/`, а сниппет активации (тот же блок с маркерами) дописать в `~/.claude/CLAUDE.md`.
2. **В каждом проекте** всё равно создать `<проект>/.claude/amg/config.yml` с `active: true` и источниками: движок общий, **граф у каждого проекта свой**.
3. Зависимости поставить глобально.
4. Проверка — теми же командами из корня проекта.

### О маркерах `CLAUDE.md`

Блок AMG всегда заключён между `<!-- AMG:BEGIN -->` и `<!-- AMG:END -->`. При повторной установке заменяется **только** содержимое между маркерами — ваши собственные инструкции (вне маркеров) не трогаются. Если файла `CLAUDE.md` нет, он создаётся с одним этим блоком.

## Раздел 2. Автоматическая установка силами модели

Скажите модели: **«установи AMG по INSTALL.md»**. Она задаёт вопросы (с краткой справкой к каждому), затем записывает `config.yml`, размещает движок, дописывает блок в `CLAUDE.md` между маркерами, ставит выбранные зависимости и прогоняет проверку. Вопросы:

1. **Глобально или локально?** *(необязательный; по умолчанию — локально.)* Справка: локально — движок в одном проекте; глобально — движок в `~/.claude/`, но граф всё равно у каждого проекта свой.
2. **Список папок впитывания (`absorb_path`)?** *(обязательный.)* Справка: разовое сырьё (логи, дампы, экспортированные диалоги); впитывается один раз, удаление источника позже узлы не вычищает.
3. **Список зеркал (`mirror_path`)?** *(обязательный.)* Справка: то, что редактируется (код, поддерживаемые документы); граф держится равным — изменение обновляет узел, удаление вычищает.
4. **Политика сессий (`session_policy`)?** *(по умолчанию `absorb`.)* Справка: как подключать сохранённые диалоги; для ценных диалогов лучше `mirror` — тогда сохраняются все детали, а не только сводка.
5. **Эмбеддинги для семантического засева?** *(по умолчанию — лёгкий `model2vec`; можно `sentence-transformers`, своё имя модели или выключить.)* Справка: улучшают поиск по смыслу, а не только по словам; **для кириллицы** нужна многоязычная модель, например `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`.
6. **Автоматика (`automation`)?** *(по умолчанию `on`.)* Справка: при `off` система действует только по командам `/amg ...` или явному запросу.
7. **Бюджеты ярусов (стратегический / тактический / оперативный)?** *(по умолчанию 4000 / 10000 / 24000 токенов.)* Справка: потолок выдачи на запрос (не нагрузка); задаются здесь, чтобы потом не править конфиг.
8. **Поставить опциональные зависимости?** *(по умолчанию — да, по `requirements.txt`.)* Справка: tree-sitter (код прочих языков), pypdf/python-docx/openpyxl (PDF/DOCX/XLSX), модель эмбеддингов.

Правила обработки ответов: **пустые поля берут значения по умолчанию, кроме обязательных** `absorb_path` и `mirror_path` — если они пусты, переспросить. Глобально/локально при пропуске — локально. После ответов модель: записывает `config.yml`, размещает `agents/`/`skills/`, дописывает блок в `CLAUDE.md` между маркерами, ставит зависимости и прогоняет `verify --repair` + `bootstrap`, показывая итог.

## Проверка после установки

В обоих способах в конце стоит убедиться, что всё встало: `graph_store.py verify --repair` (целостность), `reconcile.py bootstrap .` (граф строится) и `extract_structure.py . --stats` (что попало в граф и каких библиотек не хватает). Если `bootstrap` сообщает ненулевую очередь — это нормально для первого прогона: семантическую фазу доведёт скилл `amg-bootstrap`.

## Опциональные зависимости

| Возможность | Установка |
|---|---|
| Код прочих языков (функции + рёбра вызовов) | `pip install tree-sitter tree-sitter-language-pack` |
| Извлечение из PDF / DOCX / XLSX | `pip install pypdf python-docx openpyxl` |
| Семантический засев (лёгкий) | `pip install model2vec` |
| Семантический засев (полные трансформеры, в т. ч. многоязычные) | `pip install sentence-transformers` |

Базовый тракт работает и без них (Python-код разбирается без зависимостей, остальные форматы при отсутствии библиотеки мягко пропускаются). Подробности использования — в [руководстве](./docs/ru/GUIDE.md).

## Удаление и переустановка

Удалить блок между маркерами `<!-- AMG:BEGIN -->` и `<!-- AMG:END -->` в `CLAUDE.md`, удалить движок (`agents/`, `skills/`) и при необходимости сам граф (`<проект>/.claude/amg/`). Переустановка заменяет только блок между маркерами и движок, не затрагивая ваши инструкции.

## Памятка

Граф всегда локальный — он живёт в `<проект>/.claude/amg/` даже при глобальной установке движка. Общего графа между проектами нет: каждая память привязана к своему проекту.
