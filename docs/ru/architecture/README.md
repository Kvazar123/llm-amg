# AMG — Архитектура

Этот набор документов описывает **реализацию** AMG: модули, форматы данных, алгоритмы, параметры конфигурации и потоки управления. Теоретические основания (модель памяти, обоснование механизмов, связь с исследованиями) вынесены отдельно — см. [теорию](../THEORY.md). Документы дополняют друг друга: теория отвечает на вопрос «почему так», архитектура — «как именно это сделано».

Архитектура описывает **AMG (Associative Memory Graph)** — постоянную консолидированную память для языковых моделей в виде графа связанных узлов поверх файловой системы. Система реализована как набор скриптов на Python, скиллов и субагентов для Claude Code; графовый движок доменно-слеп, а зависящий от типа данных слой — только на входе.

## Карта документации

Документы пронумерованы в порядке чтения «от общего к частному». Каждый посвящён одному слою или модулю.

- [01-overview.md](./01-overview.md) — общая картина: детерминированный слой и слой суждения, карта модулей, потоки данных (ингест, извлечение, консолидация).
- [02-data-model.md](./02-data-model.md) — модель данных: формат узла (frontmatter), идентификаторы, типы рёбер, физические бакеты, раскладка каталогов.
- [03-storage.md](./03-storage.md) — хранилище `graph_store.py`: атомарные записи, журнал упреждающей записи, лок на запись, восстановление и проверка; ссылка на формальную модель согласованности.
- [04-ingest.md](./04-ingest.md) — извлечение `extract_structure.py`: классификатор типов, реестр нарезателей (Python `ast`, tree-sitter, markdown, текст, JSON, PDF, DOCX, XLSX), правила игнорирования.
- [05-reconcile.md](./05-reconcile.md) — сверка `reconcile.py`: режимы `bootstrap` / `plan` / `apply`, очередь на семантическую деривацию, политики `mirror` / `absorb`, файлы `derived-*.json`.
- [06-retrieval.md](./06-retrieval.md) — извлечение `retrieve.py` и `embed.py`: лексический засев (BM25), опциональный семантический засев (эмбеддинги), Personalized PageRank, сборка пакета по ярусам, ключи конфигурации.
- [07-consolidation.md](./07-consolidation.md) — консолидация `consolidate.py`: свёртка весов (Хебб + затухание + обрезка), рубрика значимости, поэтапная компрессия веток.
- [08-agents-skills.md](./08-agents-skills.md) — субагенты и скиллы; петля активации в `CLAUDE.md`; разделение детерминированной и модельной работы по ролям.
- [09-config.md](./09-config.md) — полный справочник `config.yml`: каждый ключ, значение по умолчанию и смысл.
- [10-eval-tools.md](./10-eval-tools.md) — инструменты измерения: `eval_retrieval.py`, `inspect_graph.py`; метрики recall / precision / hop-recall.
- [11-roadmap.md](./11-roadmap.md) — заглушки нереализованного: авто-гейт eval в консолидации, слой жизненного цикла (хуки и команды), упаковка и установка, 3D-просмотр графа, командный режим и прочее отложенное.

## Статус реализации

Документы 03–07, 09, 10 описывают **реализованные и протестированные** модули. Документ [Дорожная карта](./11-roadmap.md) собирает то, что спроектировано, но ещё не реализовано; внутри прочих документов нереализованные элементы помечены явно как **(заглушка)** с краткой ссылкой на соответствующий раздел дорожной карты, чтобы при чтении было видно границу между готовым и запланированным.

## Соглашения о диаграммах

Диаграммы — это блоки `mermaid` прямо в markdown (GitHub отображает их нативно), без декоративных заливок. Конвейеры и последовательности шагов рисуются слева направо (`flowchart LR`), иерархии, деревья и карты зависимостей — сверху вниз (`flowchart TD`). Длинные процессы разбиты на несколько диаграмм по фазам, а не вытянуты в одну.
