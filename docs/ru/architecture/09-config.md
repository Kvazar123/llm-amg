# 09 — Справочник конфигурации

Вся настройка системы — в одном файле `config.yml` (управляющая плоскость, ведётся на английском). Его наличие с `active: true` включает AMG для проекта; лежит он по пути `.claude/amg/config.yml` (`.claude` — умолчание Claude Code для каталога агента; в иной среде это настроенное имя, например `.agents`, см. ключ `agent_dir`). Этот раздел перечисляет все ключи буквально, с их значениями по умолчанию и смыслом; механика, которую они настраивают, описана в профильных разделах (ссылки по ходу).

## Расположение и переопределение

Скрипты несут собственные значения по умолчанию (`DEFAULTS`), а `config.yml` их **переопределяет** — поблочно. Важны нюансы слияния:

- **Извлечение** (`retrieve.py`): блок `retrieval` накладывается на умолчания **по отдельным ключам и рекурсивно** (`_deep_merge`): вложенные блоки `relation_priors`, `token_budget`, `status_prior`, `embeddings` сливаются по отдельным ключам, поэтому неполный блок **не теряет умолчаний** — тип ребра, не названный в `config.yml`, сохраняет встроенный приоритет, а не падает до `relation_prior_default`. Встроенные умолчания в коде местами иные, чем в шаблоне (`token_budget` в коде — 1200/2500/6000/40), но значения из `config.yml` **побеждают** — действующие те, что в файле.
- **Консолидация** (`consolidate.py`): из блока `weights` берутся заданные ключи, блок `compaction` сливается по отдельным ключам. Здесь та же разница «код ≠ шаблон»: встроенные бюджеты веток в коде — `default_branch_budget_nodes` 150 / `default_branch_budget_tokens` 60000, тогда как шаблон `config.yml` задаёт 400 / 200000 (действуют значения шаблона). Параметры `near_duplicate_sim`, `episodic_types`, `stale_age_days` теперь **читаются из конфига** (ключи верхнего уровня) и присутствуют в шаблоне; при отсутствии действуют умолчания скрипта (0.82, `[section, note, open_question, plan]`, 30).

**Кэши не настраиваются.** Производный read-индекс `cache/index.sqlite` (ускоряет `load_nodes` на больших графах), кэш эмбеддингов `cache/embeddings.json` и последний пакет `cache/pack.md` конфиг-ключей не имеют: всё в `cache/` — автоматическое и одноразовое, пересобирается по необходимости («сломалось — удалить»). Подробнее — [Извлечение из графа](./06-retrieval.md).

## Активация и базовое

|---|---|---|

| `automation` | `true` | автоматизация жизненного цикла (булев, как `active`): `true` — хуки `SessionStart`/`SessionEnd` исцеляют граф, сворачивают веса и обновляют дайджест, а модель ведёт петлю сама; `false` — ничего не делается автоматически, работают только команды `/amg …`, скиллы и явные запросы (см. [Субагенты и скиллы](./08-agents-skills.md), слой жизненного цикла). Хуки и `/amg` живут в `settings.json`/`commands/` каталога агента, не в этом файле |
| `schema_version` | `2` | версия схемы конфигурации |
| `working_language` | `ru` | язык сводок документов и заметок (ISO 639-1); структурные метаданные, имена типов рёбер и идентификаторы кода остаются английскими (см. [Общая картина](./01-overview.md), две плоскости) |
| `agent_dir` | `.claude` | каталог движка и графа; `.claude` — умолчание Claude Code, в иных средах своё имя (например, `.agents`). Пишет установщик; фиксирует выбор декларативно, но корень графа ищется по расположению `amg/config.yml` цепочкой `resolve_amg_root` (см. [Хранилище](./03-storage.md) и 4.9). Для иных сред установщик подставляет имя по флагу `--env`: `codex` (skill-aware — скиллы + TOML-субагенты в `.codex/agents`) либо `generic` (переносимый блок без скиллов); см. [Субагенты и скиллы](./08-agents-skills.md), «Переносимость». Режимы кроме Claude Code пока не протестированы — Этап 19 |
| `entrypoint` | `CLAUDE.md` | файл точки входа, куда установщик вливает блок активации между маркерами `<!-- AMG:BEGIN/END -->`; `CLAUDE.md` — умолчание Claude Code, в иных средах своё имя (например, `AGENTS.md`) |

## Источники

| Ключ | Значение | Смысл |
|---|---|---|
| `mirror_path` | строка или список | папки, чьей **живой проекцией** является граф: добавлен файл → узел, изменён → обновлён, удалён → вычищен. Для того, что редактируется (код, поддерживаемые руководства) |
| `absorb_path` | строка или список | папки, **впитываемые один раз** в независимые узлы: удаление источника позже узел не вычищает, но пока источник на диске, его изменения пересверяются. Для разового материала (логи чатов, дампы данных) |
| `absorb_once_path` | строка или список | папки, **впитываемые один раз и замораживаемые**: как `absorb` (удаление источника узел не вычищает), но и последующие **изменения** источника игнорируются — узел не пересобирается. Для разового снимка, который не должен пересинхронизироваться даже при правке оригинала. На пересечении с `mirror`/`absorb` выигрывает как наиболее сохраняющая политика |
| `exclude` | список глоб-шаблонов | дополнительные исключения **поверх** встроенных умолчаний (каталог агента, `.git`, `node_modules`, `.venv`, `dist`, `build`, бинарные и т. д.) и `.gitignore`; применяются ко **всем** источникам. Обычно пуст |
| `mirror_exclude` | список глоб-шаблонов | то же, но только для зеркал (`mirror_path`); **складывается** с глобальным `exclude` |
| `absorb_exclude` | список глоб-шаблонов | то же, но только для впитываемых (`absorb_path`); складывается с `exclude` |
| `respect_gitignore` | `true` | читать ли корневой `.gitignore` (как обычный файл — git не требуется). При `false` `.gitignore` игнорируется, состав графа задаёт только конфиг |
| `session_policy` | `absorb` \| `mirror` | политика авто-выгрузок диалога: `absorb` (по умолчанию) — дамп можно удалить, останется дистиллят; `mirror` — узлы живут, пока есть файл дампа |
| `sessions` | путь (опц.) | каталог авто-выгрузок сессий; по умолчанию **вычисляется** как `<хранилище>/sessions` и корректен при любом каталоге агента — ключ нужен лишь для переопределения |

Каждый из путей — строка или YAML-список; любой можно опустить. Смысл политик `mirror`/`absorb` — в [теории](../THEORY.md) (раздел 12); поведение сверки при изменении и удалении — в разделе [Сверка и семантическое обогащение](./05-reconcile.md). Извлечение PDF/DOCX/XLSX требует установленных чисто-Python библиотек (`pip install pypdf python-docx openpyxl`); без них такие файлы пропускаются (см. [Извлечение структуры](./04-ingest.md)).

Игнорирование складывается из трёх слоёв (встроенный список каталогов → `.gitignore` → эти ключи конфига) и нигде не требует git. Важная гарантия от молчаливой потери: **явно указанный источник важнее `.gitignore`** — если корень `mirror_path`/`absorb_path` сам перечислен в `.gitignore` (типично для `absorb_path: logs`), он всё равно индексируется, тогда как мусор внутри широких источников `.gitignore` по-прежнему отсекает. Механика всех слоёв — в разделе [Извлечение структуры](./04-ingest.md), «Игнорирование».

Если же один файл попал под **два корня сразу** (пересечение `mirror_path`/`absorb_path`/`absorb_once_path`), выигрывает наиболее сохраняющая политика — `absorb_once` важнее `absorb`, та важнее `mirror`, — а сам конфликт виден в выводе `plan` (поле `policy_conflicts`) и `--stats` (`overlapping_sources` с подсказкой), то есть не разрешается молча (аудит 1.29).

Сохранённые сессии (выгрузка диалога на `SessionEnd`, [Субагенты и скиллы](./08-agents-skills.md)) — отдельный внутренний источник внутри хранилища; он ингестируется тем же трактом, что и зеркала, но обходится без префиксного игнора (см. [Извлечение структуры](./04-ingest.md), «Сессии»). В среде без хука `SessionEnd` авто-выгрузки нет — переносимая страховка «диалог не потерян» — это захват заметок по ходу (`notes.py`).

## Модели субагентов

Блок `models` распределяет силу модели по ролям — сильнейшую только на фундаментальный синтез. Он **рабочий** (audit 1.14): установщик рендерит выбор каждой роли в определения соответствующих субагентов при установке и переустановке. `config.yml` — единственный источник правды, а определения субагентов несут лишь отрендеренный результат.

| Ключ | Значение | Роль → субагенты |
|---|---|---|
| `models.structural_extraction` | `none` | извлечение структуры детерминированно, без модели (субагента нет) |
| `models.discovery` | `{haiku, low}` | лёгкие задачи только на чтение → `amg-classifier`, `amg-retriever` |
| `models.module_summary` | `sonnet` (effort по умолчанию среды) | массовая посводочная генерация сводок → `amg-builder` |
| `models.synthesis` | `{opus, high}` | обзор архитектуры, межслойные рёбра, пробелы → `amg-synth`, `amg-consolidator` |

**Структурная форма.** Значение роли — либо плоская строка-модель, либо отображение `{model, reasoning_effort}` (обратносовместимо: плоская строка продолжает работать):

```
models:
  synthesis: {model: opus, reasoning_effort: high}
```

- **`model`** — непрозрачная строка, передаётся как есть: семейный алиас Claude (`opus`/`sonnet`/`haiku`/`fable`), точный id (`claude-opus-4-8`) или id другого провайдера (например `gpt-5.5`), если Claude Code направлен на шлюз/Bedrock/Vertex. AMG строку лишь **пробрасывает**; маршрутизацию к провайдеру задаёт развёртывание (уровень `ANTHROPIC_BASE_URL`/Bedrock), а не имя модели — кастомный микро-формат версии не вводится.
- **`reasoning_effort`** — уровень рассуждения, нейтральный к среде: `minimal | low | medium | high | xhigh | max`. **Кламп по среде**: в Claude Code рендерится в поле `effort` (`low|medium|high|xhigh|max`; `minimal` сводится к `low`), в Codex — в `model_reasoning_effort` (`minimal|low|medium|high|xhigh`; `max` сводится к `xhigh`). Не задан — поле **опускается** (действует умолчание среды, у Claude Code `high`). Модель и уровень — разные параметры; уровень в имя модели не зашивается.

**Как применяется.** Установщик (`install.py`) читает `models` и пишет результат в определения субагентов: для Claude Code — поля `model`/`effort` во frontmatter `agents/amg-*.md`; для Codex — `model`/`model_reasoning_effort` в TOML `.codex/agents/amg-*.toml` (см. [Установка](../../INSTALL.md)). В средах без субагентов (skill-less) все роли исполняет один экземпляр модели, поэтому per-role тиринг там инертен.

> **Известная оговорка Claude Code.** Во frontmatter субагента поле `model:` сейчас игнорируется, если модель не передать явным параметром при запуске ([issue #44385](https://github.com/anthropics/claude-code/issues/44385)); поле `effort` при этом применяется. AMG всё равно рендерит `model:` как документированную будущепрочную поверхность; чтобы навязать модель сегодня — передать её при вызове субагента или задать переменную `CLAUDE_CODE_SUBAGENT_MODEL`.

**Дефолтный тиринг и протокол замера.** Шаблон задаёт градиент усилия рассуждения: `low` на простых read-only ролях (`discovery` — классификация типа файла, сборка пакета), полное усилие на фундаментальном синтезе (`synthesis` — явно `high`). `module_summary` оставлен **плоским** (усилие по умолчанию среды) намеренно: его посводочные сводки питают извлечение (BM25 + эмбеддинги), поэтому усилие билдера не срезается без измерения. Тиринг настраивают **числом, не на глаз** — тем же принципом «качество превыше всего», что у Хебба (§8.1 теории) и компрессии:

1. снять базу — построить граф и прогнать `eval_retrieval.py --cases …` на текущем тире;
2. понизить один тир (модель и/или `reasoning_effort`), **пересобрать** затронутые сводки/хабы (повторное обогащение через `reconcile.py bootstrap` + сборщики) и прогнать тот же eval;
3. оставить дешёвый тир там, где `recall`/`hop_recall` держатся; вернуть прежний, где просели — «дешёвая модель только там, где eval не проседает; усилие рассуждения не урезать, где качество падает».

Замер требует платных вызовов модели (пересборка графа другим тиром), поэтому **живой замер отложен** (как продуктовое включение Хебба и проверка сред Этапа 19): шаблон несёт разумные дефолты и метод, а оптимальный тир под конкретный граф подбирается измерением. `discovery: low` безопасен по построению (механические задачи); риск занижения — у `module_summary`, поэтому он и оставлен на полном усилии.

Соответствие ролей конкретным субагентам — в разделе [Субагенты и скиллы](./08-agents-skills.md).

## Веса (`weights`)

Параметры обслуживания весов на консолидации (механика — в разделе [Консолидация](./07-consolidation.md)):

| Ключ | Значение | Смысл |
|---|---|---|
| `weights.apply_hebbian` | `false` | включить обновление весов `w` (Хебб + затухание + обрезка); по умолчанию `false` — консолидация лишь копит `coact`, проводимость статична (обоснование — [теория](../THEORY.md) §8.1) |
| `weights.default_edge_weight` | 0.5 | начальный вес ребра без явного `w`; **рабочий** ключ — читается `reconcile._merge_edges` (новые смысловые рёбра), `retrieve.build_adjacency` (проводимость) и `consolidate.fold_weights` |
| `weights.hebbian_rate` | 0.10 | сила хеббовского усиления (действует при `apply_hebbian`) |
| `weights.decay_rate` | 0.02 | пассивное затухание (действует при `apply_hebbian` и наличии журнала ко-активаций) |
| `weights.prune_below` | 0.05 | порог обрезки ослабших рёбер (действует при `apply_hebbian`) |
| `weights.part_of_renormalize` | `true` | держать сумму долей членства ≤ 1 (всегда, отдельно от `apply_hebbian`) |

## Компрессия (`compaction`)

Параметры сжатия веток (механика — в разделе [Консолидация](./07-consolidation.md)):

| Ключ | Значение | Смысл |
|---|---|---|
| `compaction.enabled` | `true` | **рабочий** переключатель: при `false` план не помечает ни одной ветки, а `apply` пропускает компрессионные действия без `force`. При `true` сжатие запускается только на превышении бюджета (при щедрых бюджетах граф не сжимается) |
| `compaction.default_branch_budget_nodes` | 400 | бюджет ветки в узлах |
| `compaction.default_branch_budget_tokens` | 200000 | бюджет ветки в токенах |
| `compaction.protect_types` | `[decision, adr]` | типы, не сжимаемые первыми |
| `compaction.protect_min_centrality` | 0.7 | порог центральности для защиты узла |
| `compaction.archive_dir` | `archive` | каталог архива оригиналов |
| `compaction.steps` | `[summarize_episodes, merge_near_duplicates, introduce_subhub, lossy_shorten]` | порядок поэтапного сжатия |

## Настройки плана консолидации (верхний уровень)

Параметры разметки плана — ключи верхнего уровня конфигурации (читаются `consolidate.load_config`, присутствуют в шаблоне; при отсутствии действуют умолчания скрипта):

| Ключ | Значение | Смысл |
|---|---|---|
| `near_duplicate_sim` | 0.82 | порог близости Жаккара для пометки пары кандидатами на слияние |
| `episodic_types` | `[section, note, open_question, plan]` | типы узлов, считаемых эпизодическими (свёртка / значимость / повышение). `open_question` и `plan` — транзитные авторские состояния, которые консолидация обязана **пересматривать** (вопрос отвечён → повысить/вывести; план выполнен → вывести), а не держать вечно-`active`; `decision`/`adr` сюда не входят — они защищены (`protect_types`) |
| `stale_age_days` | 30 | основа сигнала свежести в рубрике значимости |

## Автоматическая проверка полноты (`eval_gate`)

Предохранитель, не дающий компрессии незаметно ухудшить извлечение: перед применением компрессионных действий `consolidate.py apply` измеряет полноту на копии графа и вносит изменения в реальный граф только при её удержании (механика — в разделе [Консолидация](./07-consolidation.md), «Автоматическая проверка полноты»). Читается `consolidate.load_config` (блок сливается с умолчаниями по отдельным ключам).

| Ключ | Значение | Смысл |
|---|---|---|
| `eval_gate.enabled` | `true` | включить проверку; при `false` компрессия применяется без измерения |
| `eval_gate.cases` | `.claude/skills/amg-retrieve/evals/cases.json` | файл размеченных случаев (`{id, query, gold_ids}`); путь абсолютный или относительно корня проекта |
| `eval_gate.min_recall_delta` | −0.02 | допустимая просадка `pack_recall` (дельта «после − до»; ниже → провал) |
| `eval_gate.min_hop_recall_delta` | −0.02 | допустимая просадка `hop_recall` |
| `eval_gate.on_fail` | `reject` | реакция на провал: `reject` (не вносить), `warn` (внести + зафиксировать просадку), `revert` (≡ `reject` — измерение идёт до коммита, поэтому откат не нужен) |

**Робастность по умолчанию.** Если файл `cases` отсутствует, пуст или ни один его `gold_ids` не существует в графе, проверка **пропускается** (`status: skipped`) — компрессия не блокируется ложно. Поставляемый `evals/cases.json` — нейтральный шаблон (его `gold_ids` не резолвятся), поэтому в установке без разметки предохранитель безопасно неактивен. Чтобы включить его, разметьте свои случаи (id из `inspect_graph.py`) и укажите на них `eval_gate.cases`.
