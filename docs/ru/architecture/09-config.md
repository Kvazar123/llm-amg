# 09 — Справочник конфигурации

Вся настройка системы — в одном файле `config.yml` (управляющая плоскость, ведётся на английском). Его наличие с `active: true` включает AMG для проекта; лежит он по пути `.claude/amg/config.yml`. Этот раздел перечисляет все ключи буквально, с их значениями по умолчанию и смыслом; механика, которую они настраивают, описана в профильных разделах (ссылки по ходу).

## Расположение и переопределение

Скрипты несут собственные значения по умолчанию (`DEFAULTS`), а `config.yml` их **переопределяет** — поблочно. Важны нюансы слияния:

- **Извлечение** (`retrieve.py`): блок `retrieval` накладывается на умолчания **по отдельным ключам и рекурсивно** (`_deep_merge`): вложенные блоки `relation_priors`, `token_budget`, `status_prior`, `embeddings` сливаются по отдельным ключам, поэтому неполный блок **не теряет умолчаний** — тип ребра, не названный в `config.yml`, сохраняет встроенный приоритет, а не падает до `relation_prior_default`. Встроенные умолчания в коде местами иные, чем в шаблоне (`token_budget` в коде — 1200/2500/6000/40), но значения из `config.yml` **побеждают** — действующие те, что в файле.
- **Консолидация** (`consolidate.py`): из блока `weights` берутся заданные ключи, блок `compaction` сливается по отдельным ключам. Здесь та же разница «код ≠ шаблон»: встроенные бюджеты веток в коде — `default_branch_budget_nodes` 150 / `default_branch_budget_tokens` 60000, тогда как шаблон `config.yml` задаёт 400 / 200000 (действуют значения шаблона). Параметры `near_duplicate_sim`, `episodic_types`, `stale_age_days` теперь **читаются из конфига** (ключи верхнего уровня) и присутствуют в шаблоне; при отсутствии действуют умолчания скрипта (0.82, `[section, note, open_question, plan]`, 30).

## Активация и базовое

| Ключ | Значение | Смысл |
|---|---|---|
| `active` | `true` | главный выключатель: `true` включает AMG для проекта, отсутствие файла или `false` — выключает (см. [Субагенты и скиллы](./08-agents-skills.md), петля активации). Переключается командой `/amg on`/`off` |
| `automation` | `true` | автоматизация жизненного цикла (булев, как `active`): `true` — хуки `SessionStart`/`SessionEnd` исцеляют граф, сворачивают веса и обновляют дайджест, а модель ведёт петлю сама; `false` — ничего не делается автоматически, работают только команды `/amg …`, скиллы и явные запросы (см. [Субагенты и скиллы](./08-agents-skills.md), слой жизненного цикла). Хуки и `/amg` живут в `settings.json`/`commands/` каталога агента, не в этом файле |
| `schema_version` | `2` | версия схемы конфигурации |
| `working_language` | `ru` | язык сводок документов и заметок (ISO 639-1); структурные метаданные, имена типов рёбер и идентификаторы кода остаются английскими (см. [Общая картина](./01-overview.md), две плоскости) |

## Источники

| Ключ | Значение | Смысл |
|---|---|---|
| `mirror_path` | строка или список | папки, чьей **живой проекцией** является граф: добавлен файл → узел, изменён → обновлён, удалён → вычищен. Для того, что редактируется (код, поддерживаемые руководства) |
| `absorb_path` | строка или список | папки, **впитываемые один раз** в независимые узлы: удаление источника позже узел не вычищает. Для разового материала (логи чатов, дампы данных) |
| `exclude` | список глоб-шаблонов | дополнительные исключения **поверх** встроенных умолчаний (`.git`, `node_modules`, `.venv`, `__pycache__`, `dist`, `build`, бинарные и т. д.) и `.gitignore` проекта; обычно пуст |

Каждый из путей — строка или YAML-список; любой можно опустить. Смысл политик `mirror`/`absorb` — в [теории](../THEORY.md) (раздел 12); поведение сверки при изменении и удалении — в разделе [Сверка и семантическое обогащение](./05-reconcile.md). Извлечение PDF/DOCX/XLSX требует установленных чисто-Python библиотек (`pip install pypdf python-docx openpyxl`); без них такие файлы пропускаются (см. [Извлечение структуры](./04-ingest.md)).

## Модели субагентов

Блок `models` распределяет силу модели по ролям — сильнейшую только на фундаментальный синтез:

| Ключ | Значение | Роль |
|---|---|---|
| `models.structural_extraction` | `none` | извлечение структуры детерминированно, без модели |
| `models.discovery` | `haiku` | лёгкие задачи только на чтение (классификация, извлечение) |
| `models.module_summary` | `sonnet` | массовая посводочная генерация сводок |
| `models.synthesis` | `opus` | обзор архитектуры, межслойные рёбра, отчёт о пробелах |

**Пока декларативно (1.14).** Скрипты блок `models` не читают, и механизма проброса выбранной модели в субагент ещё нет — реальная модель каждого субагента задана во frontmatter его файла в `agents/`. Блок фиксирует замысел распределения; рабочим он станет на этапе реализации 1.14 (см. [Дорожная карта](./11-roadmap.md)).

**Планируется** — структурная форма с версией и уровнем рассуждения вместо одной строки (модель и уровень рассуждения — разные параметры; в имя модели уровень не зашивается):

```
models:
  synthesis:
    model: opus        # семейство или точная версия-строка
    thinking: high      # off | low | medium | high
```

Соответствие ролей конкретным субагентам — в разделе [Субагенты и скиллы](./08-agents-skills.md).

## Извлечение (`retrieval`)

Параметры распространения активации (механика — в разделе [Извлечение из графа](./06-retrieval.md)):

| Ключ | Значение | Смысл |
|---|---|---|
| `retrieval.damping` | 0.85 | дальность растекания активации |
| `retrieval.max_hops` | 30 | потолок числа итераций степенного метода |
| `retrieval.activation_threshold` | 0.02 | отсечение узлов ниже этой итоговой активации |
| `retrieval.token_budget.strategic` | 4000 | бюджет яруса хабов/обзоров |
| `retrieval.token_budget.tactical` | 10000 | бюджет яруса модулей |
| `retrieval.token_budget.operational` | 24000 | бюджет яруса указателей на код и тел документов/заметок в фокусе |
| `retrieval.token_budget.periphery_links` | 60 | предел числа ссылок-периферии |
| `retrieval.relation_priors` | словарь | приоритет проводимости `β` по типу ребра: `documents`/`implements`/`specifies` 0.9, `calls`/`depends_on` 0.8, `defines`/`part_of` 0.7, `imports`/`refines`/`exemplifies` 0.6, `relates_to` 0.5, `supersedes`/`contradicts` 0.3 |
| `retrieval.relation_prior_default` | 0.5 | приоритет для типов, не перечисленных выше |
| `retrieval.status_prior` | словарь | множитель итоговой активации по статусу узла: `active`/`stale` 1.0, `superseded` 0.2, `disputed` 0.5 (запланирован, Этап 14); `stale` не штрафуется, а помечается в пакете |
| `retrieval.convergence_tol` | 1e-6 | порог сходимости степенного метода (по сумме модулей изменений) |
| `retrieval.seed_floor` | 0.0 | базовая масса каждому узлу (0 = чистая релевантность) |
| `retrieval.embeddings.enabled` | `auto` | `auto` (включить, если бэкенд установлен) / `on` / `off` |
| `retrieval.embeddings.backend` | `auto` | `auto` / `model2vec` / `sentence-transformers` |
| `retrieval.embeddings.model` | `""` | `""` = дефолт бэкенда по `working_language`: en → model2vec `potion-retrieval-32M` / st `all-MiniLM-L6-v2`; не-en → `potion-multilingual-128M` / `paraphrase-multilingual-MiniLM-L12-v2`. Любой HF-id переопределяет (апгрейд: `Alibaba-NLP/gte-multilingual-base`) |
| `retrieval.embeddings.blend` | 0.5 | 0 = чистый BM25 … 1 = чистая семантика |

## Веса (`weights`)

Параметры обслуживания весов на консолидации (механика — в разделе [Консолидация](./07-consolidation.md)):

| Ключ | Значение | Смысл |
|---|---|---|
| `weights.apply_hebbian` | `false` | включить обновление весов `w` (Хебб + затухание + обрезка); по умолчанию `false` — консолидация лишь копит `coact`, проводимость статична (обоснование — [теория](../THEORY.md) §8.1) |
| `weights.default_edge_weight` | 0.5 | начальный вес ребра без явного `w`; **рабочий** ключ — читается `reconcile._merge_edges` (новые смысловые рёбра), `retrieve.build_adjacency` (проводимость) и `consolidate.fold_weights` |
| `weights.hebbian_rate` | 0.10 | сила хеббовского усиления (действует при `apply_hebbian`) |
| `weights.decay_rate` | 0.02 | пассивное затухание (действует при `apply_hebbian` и наличии журнала ко-активаций) |
| `weights.prune_below` | 0.05 | порог обрезки ослабших рёбер (действует при `apply_hebbian`) |
| `weights.part_of_renormalize` | `true` | держать сумму долей членства ≤ 1 (всегда, отдельно от `apply_hebbian`) |

## Компрессия (`compaction`)

Параметры сжатия веток (механика — в разделе [Консолидация](./07-consolidation.md)):

| Ключ | Значение | Смысл |
|---|---|---|
| `compaction.enabled` | `true` | **рабочий** переключатель: при `false` план не помечает ни одной ветки, а `apply` пропускает компрессионные действия без `force`. При `true` сжатие запускается только на превышении бюджета (при щедрых бюджетах граф не сжимается) |
| `compaction.default_branch_budget_nodes` | 400 | бюджет ветки в узлах |
| `compaction.default_branch_budget_tokens` | 200000 | бюджет ветки в токенах |
| `compaction.protect_types` | `[decision, adr]` | типы, не сжимаемые первыми |
| `compaction.protect_min_centrality` | 0.7 | порог центральности для защиты узла |
| `compaction.archive_dir` | `archive` | каталог архива оригиналов |
| `compaction.steps` | `[summarize_episodes, merge_near_duplicates, introduce_subhub, lossy_shorten]` | порядок поэтапного сжатия |

## Настройки плана консолидации (верхний уровень)

Параметры разметки плана — ключи верхнего уровня конфигурации (читаются `consolidate.load_config`, присутствуют в шаблоне; при отсутствии действуют умолчания скрипта):

| Ключ | Значение | Смысл |
|---|---|---|
| `near_duplicate_sim` | 0.82 | порог близости Жаккара для пометки пары кандидатами на слияние |
| `episodic_types` | `[section, note, open_question, plan]` | типы узлов, считаемых эпизодическими (свёртка / значимость / повышение). `open_question` и `plan` — транзитные авторские состояния, которые консолидация обязана **пересматривать** (вопрос отвечён → повысить/вывести; план выполнен → вывести), а не держать вечно-`active`; `decision`/`adr` сюда не входят — они защищены (`protect_types`) |
| `stale_age_days` | 30 | основа сигнала свежести в рубрике значимости |

## Автоматическая проверка полноты (`eval_gate`)

Предохранитель, не дающий компрессии незаметно ухудшить извлечение: перед применением компрессионных действий `consolidate.py apply` измеряет полноту на копии графа и вносит изменения в реальный граф только при её удержании (механика — в разделе [Консолидация](./07-consolidation.md), «Автоматическая проверка полноты»). Читается `consolidate.load_config` (блок сливается с умолчаниями по отдельным ключам).

| Ключ | Значение | Смысл |
|---|---|---|
| `eval_gate.enabled` | `true` | включить проверку; при `false` компрессия применяется без измерения |
| `eval_gate.cases` | `.claude/skills/amg-retrieve/evals/cases.json` | файл размеченных случаев (`{id, query, gold_ids}`); путь абсолютный или относительно корня проекта |
| `eval_gate.min_recall_delta` | −0.02 | допустимая просадка `pack_recall` (дельта «после − до»; ниже → провал) |
| `eval_gate.min_hop_recall_delta` | −0.02 | допустимая просадка `hop_recall` |
| `eval_gate.on_fail` | `reject` | реакция на провал: `reject` (не вносить), `warn` (внести + зафиксировать просадку), `revert` (≡ `reject` — измерение идёт до коммита, поэтому откат не нужен) |

**Робастность по умолчанию.** Если файл `cases` отсутствует, пуст или ни один его `gold_ids` не существует в графе, проверка **пропускается** (`status: skipped`) — компрессия не блокируется ложно. Поставляемый `evals/cases.json` — нейтральный шаблон (его `gold_ids` не резолвятся), поэтому в установке без разметки предохранитель безопасно неактивен. Чтобы включить его, разметьте свои случаи (id из `inspect_graph.py`) и укажите на них `eval_gate.cases`.

## Планируется (дорожная карта)

Ключи, спроектированные, но **ещё не входящие** в шаблон (полностью — в разделе [Дорожная карта](./11-roadmap.md)):

| Ключ | Значение | Смысл |
|---|---|---|
| `session_policy` | `absorb` \| `mirror` | как сохранённая сессия подключается к графу (по умолчанию `absorb`; важную сессию можно вести зеркалом) |
| `sessions` | путь | папка для авто-выгрузки сессий хуком `SessionEnd` |
| `models.<роль>` | `{model, thinking}` | структурная форма выбора модели с версией и уровнем рассуждения (см. выше) |
| `agent_dir` / `entrypoint` | пути | каталог агента и файл точки входа; пишет установщик (Этап 10), умолчания `.claude` / `CLAUDE.md` (см. 4.9) |
| `absorb_once` / `absorb_freeze` | флаг | опциональное «впитать один раз и заморозить» — без пересверки изменений источника (Этап 11) |
| `verification` | блок | `enabled` / `verify_code_claims` / `warn_on_unverified` — слой провенанса и верификации фактов (Этап 13) |
