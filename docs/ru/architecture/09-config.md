# 09 — Справочник конфигурации

Вся настройка системы — в файле `config.yml` (управляющая плоскость, ведётся на английском). Его наличие с `active: true` включает AMG для проекта; лежит он по пути `.claude/amg/config.yml` (`.claude` — умолчание Claude Code для каталога агента; в иной среде это настроенное имя, например `.agents`, см. ключ `agent_dir`). Этот раздел перечисляет все ключи буквально, с их значениями по умолчанию и смыслом; механика, которую они настраивают, описана в профильных разделах (ссылки по ходу).

## Два слоя: глобальный и локальный конфиг

Конфигурация читается в два слоя. **Локальный** `config.yml` проекта — основной и обязательный: он включает память и несёт проектные настройки. **Глобальный** `~/<каталог агента>/amg/config.yml` — необязательный слой **личных умолчаний одной машины**, который заводит глобальная установка: загрузчики (`retrieve` / `consolidate` / `extract_structure`) читают сперва его, затем локальный, и локальный **переопределяет по отдельным ключам** (вложенные блоки сливаются рекурсивно; недостающее наследуется).

Слои разведены по принадлежности настроек. В глобальном живёт личное, что не должно навязываться команде через git-канон проекта: блок `models` (тиринг моделей) и блок `retrieval.embeddings` (бэкенд и включение засева — свойство машины, на которой стоят зависимости). Всё проектное — `active`, источники, `working_language`, `automation`, бюджеты, веса, компрессия — остаётся локальным, и команда получает его одинаковым из git. При глобальной установке локальный конфиг пишется **без** личных блоков (иначе полный шаблон затенял бы глобальный слой); при локальной — самодостаточен, глобальный слой не создаётся.

Наследование включает ключ `agent_dir` **локального** конфига (установщик пишет его всегда): он называет домашний каталог среды — у `.claude`, `.agents` и настроенного имени слои свои — и одновременно помечает конфиг как установленный; минимальный рукописный конфиг без `agent_dir` глобальный слой не читает. Каталог `~/<каталог агента>/amg/` — носитель одного файла, **не хранилище**: разрешение store его не выбирает (см. [Хранилище](./03-storage.md)). Механика записи слоёв установщиком — [12-install](./12-install.md).

## Расположение и переопределение

Скрипты несут собственные значения по умолчанию (`DEFAULTS`), а `config.yml` (объединённый из двух слоёв, см. выше) их **переопределяет** — поблочно. Важны нюансы слияния:

- **Извлечение** (`retrieve.py`): блок `retrieval` накладывается на умолчания **по отдельным ключам и рекурсивно** (`_deep_merge`): вложенные блоки `relation_priors`, `token_budget`, `status_prior`, `embeddings` сливаются по отдельным ключам, поэтому неполный блок **не теряет умолчаний** — тип ребра, не названный в `config.yml`, сохраняет встроенный приоритет, а не падает до `relation_prior_default`. Встроенные умолчания в коде местами иные, чем в шаблоне (`token_budget` в коде — 1200/2500/6000/40), но значения из `config.yml` **побеждают** — действующие те, что в файле.
- **Консолидация** (`consolidate.py`): из блока `weights` берутся заданные ключи, блок `compaction` сливается по отдельным ключам. Здесь та же разница «код ≠ шаблон»: встроенные бюджеты веток в коде — `default_branch_budget_nodes` 150 / `default_branch_budget_tokens` 60000, тогда как шаблон `config.yml` задаёт 400 / 200000 (действуют значения шаблона). Параметры `near_duplicate_sim`, `episodic_types`, `stale_age_days` теперь **читаются из конфига** (ключи верхнего уровня) и присутствуют в шаблоне; при отсутствии действуют умолчания скрипта (0.82, `[section, note, open_question, plan]`, 30).
- **Сверка** (`reconcile.py`): ключ `trivial_unit_max_lines` — третий случай «код ≠ шаблон»: встроенное умолчание кода `0` (авто-сводка тривиальных единиц выключена — минимальный рукописный конфиг ведёт себя по-старому), а поставляемый шаблон включает `3` (см. «Очередь и партии сборки» ниже).

**Одноразовые кэши не настраиваются.** Производный read-индекс `cache/index.sqlite` (ускоряет `load_nodes` на больших графах), кэш эмбеддингов `cache/embeddings.json` и последний пакет `cache/pack.md` конфиг-ключей не имеют: они автоматические и одноразовые, пересобираются по необходимости («сломалось — удалить»). Исключение — **кэш обогащения** `cache/derivations/`: он меняет поведение пересборки (восстанавливает сводки вместо новой генерации), поэтому у него есть выключатель `derivation_cache` (ниже). Подробнее — [Извлечение из графа](./06-retrieval.md) и [Сверка](./05-reconcile.md).

## Активация и базовое

| Ключ | Значение | Смысл |
|---|---|---|
| `active` | `true` | главный выключатель: `true` включает AMG для проекта, отсутствие файла или `false` — выключает (см. [Субагенты и скиллы](./08-agents-skills.md), петля активации). Переключается командой `/amg on`/`off` |
| `automation` | `true` | автоматизация жизненного цикла (булев, как `active`): `true` — хуки `SessionStart`/`SessionEnd` исцеляют граф, сворачивают веса и обновляют дайджест, а модель ведёт петлю сама; `false` — ничего не делается автоматически, работают только команды `/amg …`, скиллы и явные запросы (см. [Субагенты и скиллы](./08-agents-skills.md), слой жизненного цикла). Хуки и `/amg` живут в `settings.json`/`commands/` каталога агента, не в этом файле |
| `schema_version` | `3` | версия схемы конфигурации |
| `working_language` | `ru` | язык сводок документов и заметок (ISO 639-1); структурные метаданные, имена типов рёбер и идентификаторы кода остаются английскими (см. [Общая картина](./01-overview.md), две плоскости) |
| `agent_dir` | `.claude` | каталог движка и графа; `.claude` — умолчание Claude Code, в иных средах своё имя (например, `.agents`). Пишет установщик; фиксирует выбор декларативно (корень графа ищется по расположению `amg/config.yml` цепочкой `resolve_amg_root` — см. [Хранилище](./03-storage.md)) и **включает наследование глобального слоя** (см. «Два слоя» выше): без этого ключа глобальный конфиг не читается. Для иных сред установщик подставляет имя по флагу `--env`: `codex` (skill-aware — скиллы + TOML-субагенты в `.codex/agents`) либо `generic` (переносимый блок без скиллов); см. [Субагенты и скиллы](./08-agents-skills.md), «Переносимость». Режимы кроме Claude Code пока не протестированы — проверка сред впереди по дорожной карте |
| `entrypoint` | `CLAUDE.md` | файл точки входа, куда установщик вливает блок активации между маркерами `<!-- AMG:BEGIN/END -->`; `CLAUDE.md` — умолчание Claude Code, в иных средах своё имя (например, `AGENTS.md`) |

## Источники

| Ключ | Значение | Смысл |
|---|---|---|
| `mirror_path` | строка или список | папки, чьей **живой проекцией** является граф: добавлен файл → узел, изменён → обновлён, удалён → вычищен. Для того, что редактируется (код, поддерживаемые руководства) |
| `absorb_path` | строка или список | папки, **впитываемые один раз** в независимые узлы: удаление источника позже узел не вычищает, но пока источник на диске, его изменения пересверяются. Для разового материала (логи чатов, дампы данных) |
| `absorb_once_path` | строка или список | папки, **впитываемые один раз и замораживаемые**: как `absorb` (удаление источника узел не вычищает), но и последующие **изменения** источника игнорируются — узел не пересобирается. Для разового снимка, который не должен пересинхронизироваться даже при правке оригинала. На пересечении с `mirror`/`absorb` выигрывает как наиболее сохраняющая политика |
| `exclude` | список глоб-шаблонов | дополнительные исключения **поверх** встроенных умолчаний (каталог агента, `.git`, `node_modules`, `.venv`, `dist`, `build`, бинарные и т. д.) и `.gitignore`; применяются ко **всем** источникам. Обычно пуст |
| `mirror_exclude` | список глоб-шаблонов | то же, но только для зеркал (`mirror_path`); **складывается** с глобальным `exclude` |
| `absorb_exclude` | список глоб-шаблонов | то же, но только для впитываемых (`absorb_path`); складывается с `exclude` |
| `respect_gitignore` | `true` | читать ли корневой `.gitignore` (как обычный файл — git не требуется; правила применяются в порядке строк, побеждает последнее совпавшее, правила-возвраты `!` действуют). При `false` `.gitignore` игнорируется, состав графа задаёт только конфиг |
| `session_policy` | `absorb` \| `mirror` | политика авто-выгрузок диалога: `absorb` (по умолчанию) — дамп можно удалить, останется дистиллят; `mirror` — узлы живут, пока есть файл дампа |
| `sessions` | путь (опц.) | каталог авто-выгрузок сессий; по умолчанию **вычисляется** как `<хранилище>/sessions` и корректен при любом каталоге агента — ключ нужен лишь для переопределения |

Каждый из путей — строка или YAML-список; любой можно опустить. Смысл политик `mirror`/`absorb` — в [теории](../THEORY.md) (раздел 12); поведение сверки при изменении и удалении — в разделе [Сверка и семантическое обогащение](./05-reconcile.md). Извлечение PDF/DOCX/XLSX требует установленных чисто-Python библиотек (`pip install pypdf python-docx openpyxl`); без них такие файлы пропускаются (см. [Извлечение структуры](./04-ingest.md)).

Для обратной совместимости поддерживается и устаревшая форма перечисления источников — словарь `sources: {имя: {path, policy}}` (`resolve_sources` читает его, только если не задан ни один из ключей `mirror_path`/`absorb_path`/`absorb_once_path`). В новых конфигурациях используйте три ключа выше; шаблон устаревшую форму не несёт.

Игнорирование складывается из трёх слоёв (встроенный список каталогов → `.gitignore` → эти ключи конфига) и нигде не требует git. Важная гарантия от молчаливой потери: **явно указанный источник важнее `.gitignore`** — если корень `mirror_path`/`absorb_path` сам перечислен в `.gitignore` (типично для `absorb_path: logs`), он всё равно индексируется, тогда как мусор внутри широких источников `.gitignore` по-прежнему отсекает. Механика всех слоёв — в разделе [Извлечение структуры](./04-ingest.md), «Игнорирование».

Если же один файл попал под **два корня сразу** (пересечение `mirror_path`/`absorb_path`/`absorb_once_path`), выигрывает наиболее сохраняющая политика — `absorb_once` важнее `absorb`, та важнее `mirror`, — а сам конфликт виден в выводе `plan` (поле `policy_conflicts`) и `--stats` (`overlapping_sources` с подсказкой), то есть не разрешается молча.

Сохранённые сессии (выгрузка диалога на `SessionEnd`, [Субагенты и скиллы](./08-agents-skills.md)) — отдельный внутренний источник внутри хранилища; он загружается тем же трактом, что и зеркала, но обходится без префиксного игнора (см. [Извлечение структуры](./04-ingest.md), «Сессии»). В среде без хука `SessionEnd` авто-выгрузки нет — переносимая страховка «диалог не потерян» — это захват заметок по ходу (`notes.py`).

## Нарезка входа

Числовые пределы нарезателей структурированных и неструктурированных данных (механика — [Извлечение структуры](./04-ingest.md)). Все ключи опциональны; при отсутствии действуют показанные умолчания.

| Ключ | Значение | Смысл |
|---|---|---|
| `json_max_depth` | 4 | до какой глубины рекурсивный JSON-нарезатель спускается во вложенные контейнеры |
| `json_recurse_min_chars` | 2048 | спускаться внутрь контейнера, только если его сериализованный JSON длиннее этого порога; мелкие и плоские значения остаются одной записью (с прежними id и хешами) |
| `json_max_nodes` | 500 | предел числа записей-единиц с одного JSON- или NDJSON-файла |
| `log_group_lines` | 50 | сколько строк журнала (`.log`) объединяется в один эпизод-блок |

## Очередь и партии сборки

Ключи экономной сборки: сколько текста едет в очередь работ, какие единицы выводятся без модели и каков размер одной партии сборщика (механика — [Сверка](./05-reconcile.md), «Очередь обогащения» и «Авто-сводка тривиальных единиц»; оркестрация — [Субагенты и скиллы](./08-agents-skills.md)).

| Ключ | Значение | Смысл |
|---|---|---|
| `queue_text_max_chars` | 20000 | потолок (в символах) на текст единицы, вкладываемый в элемент `work/queue.json`: сборщик пишет сводку прямо из очереди и не перечитывает источники; текст свыше порога не вкладывается — такой элемент несёт только указатель. `0` — очередь целиком без текстов (как до появления ключа) |
| `trivial_unit_max_lines` | 3 (шаблон) | функция кода, чьё определение занимает не больше этого числа строк, выводится **детерминированной авто-сводкой** (её собственный код одной строкой) без вызова модели и без очереди; протокольные дандеры (`__call__`, `__enter__`, `__getitem__`, …) всегда идут к модели, а единица с попаданием в кэше обогащения восстанавливает заработанную сводку (кэш побеждает шаблон). Ещё один случай «код ≠ шаблон»: встроенное умолчание кода — `0` (выключено), экономию включает поставляемый шаблон |
| `builder.batch_units` | 60 | единиц в одной партии сборщика (`partition_queue.py` дробит группу-поддерево на части `queue-<партия>-NN.json`). Размер разменивает фикс-оверхед среды на каждый шаг (системный промпт и схемы инструментов переотправляются на каждом шаге каждого агента — масштабируется числом агентов, не объёмом работы) на цену потери оборванной партии; качество от размера партии не зависит, а контрольные части по ~10 единиц держат предел потери прежним, поэтому растить сильно выше умолчания почти бессмысленно |
| `builder.batch_max_chars` | 120000 | оценка входного объёма одной партии — сумма вложенных текстов (единица без текста считается номиналом 2000); ограничивает контекст одного сборщика и косвенно его вывод — симметрично `linker.batch_nodes` у линковщика |

## Модели субагентов

Блок `models` распределяет силу модели по ролям — сильнейшую только на фундаментальный синтез. Он **рабочий**: установщик рендерит выбор каждой роли в определения соответствующих субагентов при установке и переустановке. `config.yml` — единственный источник правды, а определения субагентов несут лишь отрендеренный результат.

| Ключ | Значение | Роль → субагенты |
|---|---|---|
| `models.structural_extraction` | `none` | извлечение структуры детерминированно, без модели (субагента нет) |
| `models.discovery` | `{haiku, low}` | лёгкие задачи только на чтение → `amg-classifier`, `amg-retriever` |
| `models.module_summary` | `sonnet` (effort по умолчанию среды) | массовая работа с ограниченным контекстом: посводочная генерация → `amg-builder`; подтверждение кандидатов линковки → `amg-linker` (сила линковки — в глобальности кандидатов, не в размере модели) |
| `models.synthesis` | `{opus, high}` | обзор архитектуры, межслойные рёбра, пробелы → `amg-synth`, `amg-consolidator` |

**Структурная форма.** Значение роли — либо плоская строка-модель, либо отображение `{model, reasoning_effort}` (обратносовместимо: плоская строка продолжает работать):

```
models:
  synthesis: {model: opus, reasoning_effort: high}
```

- **`model`** — непрозрачная строка, передаётся как есть: семейный алиас Claude (`opus`/`sonnet`/`haiku`/`fable`), точный id (`claude-opus-4-8`) или id другого провайдера (например `gpt-5.5`), если Claude Code направлен на шлюз/Bedrock/Vertex. AMG строку лишь **пробрасывает**; маршрутизацию к провайдеру задаёт развёртывание (уровень `ANTHROPIC_BASE_URL`/Bedrock), а не имя модели — кастомный микро-формат версии не вводится.
- **`reasoning_effort`** — уровень рассуждения, нейтральный к среде: `minimal | low | medium | high | xhigh | max`. **Кламп по среде**: в Claude Code рендерится в поле `effort` (`low|medium|high|xhigh|max`; `minimal` сводится к `low`), в Codex — в `model_reasoning_effort` (`minimal|low|medium|high|xhigh`; `max` сводится к `xhigh`). Не задан — поле **опускается** (действует умолчание среды, у Claude Code `high`). Модель и уровень — разные параметры; уровень в имя модели не зашивается.

**Как применяется.** Установщик (`install.py`) читает `models` и пишет результат в определения субагентов: для Claude Code — поля `model`/`effort` во frontmatter `agents/amg-*.md`; для Codex — `model`/`model_reasoning_effort` в TOML `.codex/agents/amg-*.toml` (см. [Установка](../../../INSTALL_RU.md)). В средах без субагентов (skill-less) все роли исполняет один экземпляр модели, поэтому per-role тиринг там инертен.

> **Известная оговорка Claude Code.** Во frontmatter субагента поле `model:` сейчас игнорируется, если модель не передать явным параметром при запуске ([issue #44385](https://github.com/anthropics/claude-code/issues/44385)); поле `effort` при этом применяется. AMG всё равно рендерит `model:` как документированную будущепрочную поверхность; чтобы навязать модель сегодня — передать её при вызове субагента или задать переменную `CLAUDE_CODE_SUBAGENT_MODEL`.

**Дефолтный тиринг и протокол замера.** Шаблон задаёт градиент усилия рассуждения: `low` на простых read-only ролях (`discovery` — классификация типа файла, сборка пакета), полное усилие на фундаментальном синтезе (`synthesis` — явно `high`). `module_summary` оставлен **плоским** (усилие по умолчанию среды) намеренно: его посводочные сводки питают извлечение (BM25 + эмбеддинги), поэтому усилие билдера не срезается без измерения. Тиринг настраивают **числом, не на глаз** — тем же принципом «качество превыше всего», что у Хебба (§8.1 теории) и компрессии:

1. снять базу — построить граф и прогнать `eval_retrieval.py --cases …` на текущем тире;
2. понизить один тир (модель и/или `reasoning_effort`), **пересобрать** затронутые сводки/хабы (повторное обогащение через `reconcile.py bootstrap` + сборщики) и прогнать тот же eval;
3. оставить дешёвый тир там, где `recall`/`hop_recall` держатся; вернуть прежний, где просели — «дешёвая модель только там, где eval не проседает; усилие рассуждения не урезать, где качество падает».

Замер требует платных вызовов модели (пересборка графа другим тиром), поэтому **живой замер отложен** (как продуктовое включение Хебба и проверка не-Claude-Code-сред): шаблон несёт разумные дефолты и метод, а оптимальный тир под конкретный граф подбирается измерением. `discovery: low` безопасен по построению (механические задачи); риск занижения — у `module_summary`, поэтому он и оставлен на полном усилии.

Блок `models` — типичный обитатель **глобального** слоя конфигурации (см. «Два слоя» выше): тиринг — личное предпочтение машины, а не проекта, и при глобальной установке он живёт в `~/<каталог агента>/amg/config.yml`, наследуясь каждым проектом; локальный блок `models`, если задан, переопределяет его по отдельным ролям. Установщик рендерит субагентов из объединённого взгляда обоих слоёв.

Соответствие ролей конкретным субагентам — в разделе [Субагенты и скиллы](./08-agents-skills.md).

## Стратегия обогащения (`derivation`)

Ключ верхнего уровня `derivation` (`eager` | `lazy`, умолчание **`eager`**) задаёт, сколько семантического слоя строится при `bootstrap`:

| Значение | Поведение |
|---|---|
| `eager` (умолчание) | деривировать сводку + смысловые рёбра для **каждой** единицы очереди сразу при построении |
| `lazy` | деривировать сразу только структурную **карту** (module/class/package/file + хабы синтеза), отложив листовую детализацию (функции, разделы документов, записи) до первого обращения запросом; активированный отложенный узел деривируется **синхронно до ответа** (первое касание не бывает пустым), фоновый проход добирает остальное по `usage.log` |

`lazy` разменивает начальную стоимость на просадку качества у ещё-не-деривированных узлов ([дорожная карта, §4.10](./11-roadmap.md)) и окупается **только** на графе много большем, чем он реально опрашивается; на малом графе оставлять `eager`. Дефолт остаётся `eager`, пока измерение на большом графе не подтвердит приемлемость размена (протокол off/on) — это явный opt-in, а не авто-режим по размеру. **Предохранители:** структурный скелет и стратегический синтез не откладываются никогда; первое касание активированного узла синхронно (`retrieve.stale_in_pack` → сборщик до ответа); откладывание ничего не теряет (источник и структурный узел на месте). Замер off/on (первое касание держит многошаговость, голая лень — рвёт) — §4.10 и `../amg-bigtest/README.md`. Ветвление режима — на уровне скиллов `amg-bootstrap`/`amg-retrieve` и хелпера `partition_queue.py --priority`; сам движок на флаг не ветвится.

## Кэш обогащения (`derivation_cache`)

Ключ верхнего уровня `derivation_cache` (булев, умолчание **`true`**) включает постоянный кэш применённого обогащения (`cache/derivations/`, ключ — хеш содержимого единицы + версия контракта + `working_language`): пересборка восстанавливает сводки и рёбра дословно и почти бесплатно, `bootstrap` делает это автоматически (поле `restored_from_cache` в сводке). `false` — деривировать заново (например, после смены модели); тот же эффект даёт удаление каталога. Механика — [Сверка](./05-reconcile.md), «Кэш обогащения»; обоснование — [теория, §4.3](../THEORY.md).

## Автоматическая проверка полноты (`eval_gate`)

Предохранитель, не дающий компрессии незаметно ухудшить извлечение: перед применением компрессионных действий `consolidate.py apply` измеряет полноту на копии графа и вносит изменения в реальный граф только при её удержании (механика — в разделе [Консолидация](./07-consolidation.md), «Автоматическая проверка полноты»). Читается `consolidate.load_config` (блок сливается с умолчаниями по отдельным ключам).

| Ключ | Значение | Смысл |
|---|---|---|
| `eval_gate.enabled` | `true` | включить проверку; при `false` компрессия применяется без измерения |
| `eval_gate.cases` | `.claude/amg/evals/cases.json` | файл размеченных случаев (`{id, query, gold_ids}`); путь абсолютный или относительно корня проекта. Он лежит **под хранилищем** намеренно: переустановка движка целиком заменяет дерево скиллов и стёрла бы разметку, лежащую там, а хранилище не трогается никогда |
| `eval_gate.min_recall_delta` | −0.02 | допустимая просадка `pack_recall` (дельта «после − до»; ниже → провал) |
| `eval_gate.min_hop_recall_delta` | −0.02 | допустимая просадка `pack_hop_recall` (пакетная hop-метрика; hop-эталон заморожен от базлайна) |
| `eval_gate.on_fail` | `reject` | реакция на провал: `reject` (не вносить), `warn` (внести + зафиксировать просадку), `revert` (≡ `reject` — измерение идёт до коммита, поэтому откат не нужен) |

**Робастность по умолчанию.** Если файл `cases` отсутствует, пуст или ни один его `gold_ids` не существует в графе, проверка **пропускается** (`status: skipped`) — компрессия не блокируется ложно. В свежей установке файла по умолчанию просто ещё нет, поэтому предохранитель безопасно неактивен. Чтобы включить его, разметьте свои случаи (id из `inspect_graph.py`) и запишите файл по умолчальному пути под хранилищем.

## Провенанс и верификация (`verification`)

Слой доверия (механика — [Извлечение из графа](./06-retrieval.md), «Слой доверия», теория — [§15](../THEORY.md)): каждый факт несёт происхождение и уверенность, а утверждение о коде проверяется по живому источнику до ответа. Блок верхнего уровня (поднимается в `retrieve.load_config` поверх умолчаний; `default_confidence` читает `reconcile.apply_derivation`). Пометка **не понижает** активацию — непроверенный/устаревший/спорный/малоуверенный узел флагуется в пакете, как и `stale`.

| Ключ | Значение | Смысл |
|---|---|---|
| `verification.enabled` | `true` | главный выключатель слоя пометок; при `false` пакет несёт только флаг `stale` |
| `verification.verify_code_claims` | `true` | петля запускает `verify_claims.py` на code-утверждении перед ответом (file/symbol/hash); влияет и на пометку непроверенных code-узлов |
| `verification.warn_on_unverified` | `true` | помечать в пакете непроверенный (`unverified`) code-узел |
| `verification.min_confidence_warn` | `0.5` | помечать узел, чья `confidence` ниже порога |
| `verification.default_confidence` | `0.7` | уверенность для выведенной сводки, которой сборщик не дал явной оценки (читается при применении обогащения) |

`verify_claims.py` (read-only по умолчанию; `--write` стэмпит блок `verification` узла для аудит-прохода) и пометка пакета описаны в [Извлечение из графа](./06-retrieval.md). Поля узла `confidence`/`provenance`/`verification` — в [Модели данных](./02-data-model.md), «Слой доверия».

## Просмотр графа (`viewer`)

Блок настраивает 3D-вьюер графа (`export_graph.py` → самодостаточный офлайн-HTML; механика — [Измерение и инструменты](./10-eval-tools.md)). Это **тонкий слой** над библиотекой `3d-force-graph`: несколько ключей с понятными именами AMG плюс сквозной passthrough `options`, чтобы конфиг не перечислял всю поверхность библиотеки. Все ключи необязательны; экспортёр кладёт блок в `meta` HTML, вьюер читает его как умолчания (интерфейс позволяет менять на лету).

| Ключ | Значение | Смысл |
|---|---|---|
| `viewer.quality` | `auto` | гладкость узлов и рёбер (число сегментов сфер/трубок): `auto` (выше на малых графах, ниже на больших) / `high` / `medium` / `low` |
| `viewer.large_graph_mode` | `auto` | режим большого графа **на старте**: `auto` (включить, когда узлов больше `large_graph_nodes`) / `on` (всегда — для графа, который иначе подвиснет) / `off` (показать всё сразу). Стартовое состояние «запекается» в HTML, поэтому смена требует повторного экспорта; кнопка во вьюере переключает на лету |
| `viewer.large_graph_nodes` | `1500` | порог числа узлов, выше которого `large_graph_mode: auto` включается |
| `viewer.min_edge_weight` | `0.0` | стартовое положение ползунка «скрыть слабые рёбра» (0 = показывать все) |
| `viewer.options` | `{}` | **сквозной passthrough**: отображение «имя метода `3d-force-graph` → его аргумент», применяемое к графу как есть (битый ключ/значение молча игнорируется) — так конфиг не дублирует ключи библиотеки. Полный их список — [API-справочник `3d-force-graph`](https://github.com/vasturiano/3d-force-graph#api-reference) |

YAML трактует голые `on`/`off` как булевы `true`/`false`; вьюер принимает и булево, и строку, поэтому `large_graph_mode: on` срабатывает как ожидается.
